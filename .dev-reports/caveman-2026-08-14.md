# Caveman Review — A3.0

| Area | Status |
|---|---|
| Identity model | One table, unique (provider, phone), no role/capability columns |
| Actor resolution | Two lookups + membership check; null or trusted context |
| Transient store | Five methods; one Redis implementation; no fallback |
| Confirmation | Save/get/consume/clear over one namespaced key |
| Idempotency | One claim function over SET NX EX |
| Provisioning | One strict POST route, service-side authority |
| Follow-up | Keep webhook transport thin in A3.1; no new abstractions |

One dead helper in a test fake was removed. No unnecessary framework or pattern was added.

# Caveman Review — A3.1 (appended 2026-08-15)

| Area | Status |
|---|---|
| Provider | One interface, one Meta implementation; no provider factory/registry |
| Webhook route | GET handshake + raw-body POST; thin, delegates to adapter |
| Adapter | One `handleWhatsAppInboundText`; linear flow, no strategy objects |
| Reply formatting | Deterministic literal PT-BR strings; list cap constant; no template engine |
| Runtime wiring | Lazy singletons (3 getters), no DI container |
| Env | 4 optional vars; fail-closed when absent |
| Test fakes | One in-memory store, one queue-based model; no mocking framework |

No unnecessary abstraction added: the provider interface exists only because Meta is not the only conceivable provider, and it has exactly one consumer. All confirmation/idempotency logic reuses 17a primitives instead of duplicating them.
